# libs/ui — CLAUDE.md Summary

Condensed from the 1,339-line `libs/ui/CLAUDE.md`. Every rule, invariant and extension point needed to keep building is kept; only narrative detail and milestone history were cut.

## What the library is

`ws::ui::App` is an application shell over GLFW (desktop) or NativeActivity (Android), Vulkan, Dear ImGui (docking) and ImPlot. Apps subclass `App` and **never touch GLFW, Vulkan or ImGui**. Five layers:

- **Windowing + events:** Hazel-style typed events and an `EventDispatcher`.
- **`RenderCommandQueue`:** the seam between app logic and GPU work.
- **`widgets.hpp`:** the ImGui/ImPlot-backed wrapper.
- **`r2d`:** the 2D renderer.
- **`gui/`:** an immediate-mode widget set that draws through r2d; the job-row helpers bridge `ws::jobs` and the theme-json layer bridges `ws::settings` (both workspace deps of the same purity class as core/input — pure std, no platform).

Since stage 3, the input family lives in `libs/input`, and the Vulkan device, swapchain, frame sync and VMA live in `libs/gfx`. `ui` holds a `gfx::Gpu` and a `gfx::Swapchain`; `app.cpp` is the only place their opaque handles are cast.

## Hard rules (do not break)

1. **No leaking dependencies.** No third-party, GLFW, Vulkan or ImGui type or header may appear under `include/`. Before adding any public API ask: *could a consumer compile this header without Vulkan/GLFW/ImGui installed?* If not, it is a leak.
2. **Pimpl.** All third-party state lives behind a pimpl in `src/app/app.cpp` and `src/platform/window_*.cpp`. GLFW callbacks are file-local statics in `window_glfw.cpp` only, never declared in a header.
3. **New ImGui-layer widgets** go in `src/widgets/widgets.cpp`, never through an exposed third-party header.
4. **Error handling.** New public APIs return `ws::core::Result` / `Status`. The old surface predates the rule: `App::run()` returns int, drop-safe calls log and ignore, mid-frame Vulkan failures abort.
5. **Implementation rules:**
   - volk only; never link the Vulkan loader directly (`VK_NO_PROTOTYPES`).
   - VMA only in `libs/gfx` (single `VMA_IMPLEMENTATION` TU, `vma_impl.cpp`).
   - STB implementations only in `src/text/stb_impl.cpp`.
   - Don't use the `ImGui_ImplVulkanH_*` example helpers.
   - SPIR-V (`src/render/shaders/spirv.h`) is generated by `tools/compile_shaders.ps1` and committed. The pinned compiler is glslang 16.6.0. Flags live only in the script.

## Event system

- Event types: `WindowClose`, `WindowResize`, `KeyPressed`, `KeyReleased`, `MouseButtonPressed`, `MouseButtonReleased`, `MouseMoved`, `MouseScrolled`, `TouchPressed`, `TouchMoved`, `TouchReleased`, `TextInput`.
- Touch events carry `pointer_id` and `x`/`y` in framebuffer pixels. `TouchReleasedEvent` adds `cancelled`. `TextInputEvent` is one UTF-32 codepoint per event.
- `EventDispatcher(Event&)::dispatch<T>(fn)` calls `fn` only on a type match and sets `handled` from its return value.
- `on_event` runs synchronously on the main thread before `on_update()`.
- Coalescing: mouse move (latest position), scroll (summed), `TouchMoved` (latest per pointer id). `TextInput` never coalesces.
- ImGui gets first refusal through `WantCaptureMouse` / `WantCaptureKeyboard`. `WindowResize` / `WindowClose` always deliver. **Touch events are never ImGui-gated** (ImGui is fed by a touch→mouse bridge). `TextInput` gates like `KeyPressed`.
- Zero-size resize events (Windows minimize) are suppressed.

## Render command queue

A bump-allocated double buffer. The app submits into the write queue, and the shell swaps and executes the read queue. A frame that can't render (out-of-date acquire, hidden window) clears the write queue, so a command never outlives its frame. Future non-ImGui GPU work (overlays, offscreen passes) goes here.

## r2d (2D renderer)

- **API** (`ws::ui::r2d`): `begin()` / `begin(camera)` / `begin(Camera3D)` / `end()`, `draw_quad`, `draw_line`, `draw_sprite`, `draw_rounded_quad`, `set_layer`, `push_clip` / `pop_clip` / `push_clip_escape`, `load_texture`, `load_texture_from_memory`, `destroy_texture`, `load_atlas`, `load_font`, `draw_text`, `frame_size`, `sprite_size`, `stats`, `rgba` (0xRRGGBBAA, not IM_COL32 order).
- **Drawing rules:** record from `on_update()` only. All calls are drop-safe outside a running app.
- **Recording is data.** Each draw appends a `DrawCommand`. `frame_end()` stable-sorts by (layer, camera block) only. Material and clip are deliberately not sort keys; a clip change splits a chunk in record order. **Draw each clipped panel's content contiguously.**
- **Clip stack:** depth cap 8, balanced overflow, no-op pop on empty, reset every frame. `push_clip_escape` pushes without the intersect (for overlays).
- **Chunks:** one VP + one clip + one depth mode + one texture table + one draw. No drop caps; vectors grow geometrically at flush. At most 16384 quads per chunk (u16 indices, chunk-local). The only remaining drop is a quad pushed with no open segment.
- **Textures:**
  - `load_*` is valid from `on_setup()`, uploads synchronously and returns white on failure.
  - id 0 is built-in white.
  - Handles are generation-counted (`(gen << 20) | slot`). A stale handle renders white.
  - Frees are reclaimed `kMaxFramesInFlight` frames later.
  - Two tiers, picked once by `gfx::Gpu`:
    - **Bindless:** one 1024-slot global table.
    - **Chunked:** a 32-slot table per chunk.
- **Atlases:** 2048² pages, shelf packing, 1px gutters. `Sprite{page, index}`. A failed image becomes `Sprite{}` (white).
- **Fonts and text:** `load_font(path, pixel_height)` bakes ASCII 32..126 into the font's own atlas pages (never shared with sprites, by design). `draw_text` returns the advance (equals `Font::measure_text`). No kerning. Unknown codepoints draw a tofu box. Glyph origins round to whole pixels on an axis-aligned zoom-1 2D camera. `utf8_next` is forgiving (bad bytes become U+FFFD). Font path resolution is the caller's job.
- **The growing font (stage 10):** a Font can stack more typeface files under its inline bake and rasterize their glyphs lazily — three owner-thread free functions in `r2d`:
  - `font_add_face(font, path, priority)` appends a face to the font's internal stack. Resolution is per codepoint: lower `priority` answers first, ties keep addition order, the same file may stack twice. Fails `FontError::font_empty` on a never-baked font and `FontError::face_load_failed` on a missing/invalid file (category "ui", codes append-only); a failure leaves the stack untouched. A hand-built font (fill ctor) borrows its first added face's ascent as the shared baseline; `load_font` sets it from the primary bake's own ascent.
  - `font_request_text(font, utf8)` marks the text's out-of-bake codepoints that some stacked face carries (not yet baked, not queued) as pending; returns how many were newly marked. Idempotent; **re-request after adding a face** — a request made before the face found nobody carrying.
  - `font_bake_pending(font, batch_cap = 64)` bakes from the queue's front (request order) into **fresh atlas pages, one pack per batch** (`atlas::pack` is one-shot) and one texture upload per page. Headless it still fills the metrics — sprites stay `Sprite{}` and `draw_text` drops the quad but keeps the advance — and it never warns: filling the font is the job, only the upload half waits for a renderer. Blanks (no bitmap, no advance) leave the queue with no entry; the fallback box keeps answering them.
  - **Copies share the growing half.** Every `Font` constructor eagerly allocates an internal `FontExtra` (`shared_ptr`); a copy IS the same font — a face added through either shows in both, and lazily-baked glyph pointers are identical. One font stays one size; a size change is a new font.
  - `FaceBake` (internal, `src/text/font.h`) is move-only: its `stbtt_fontinfo` points into its own `bytes` vector, so a copy would strand those pointers at the donor's freed buffer — copy operations are deleted; `std::move` on a `const FaceBake` is a compile error, not silent corruption.
- **Rounded quads:** an analytic SDF in `batch.frag`. The radius rides the `tex_index` channel as a negative value (`-radius/w`). It takes no texture slot, and the radius clamps to half the shorter side.
- **3D:** `begin(Camera3D)` opens a perspective block. `draw_quad(x,y,z,...)` and `draw_sprite(x,y,z,...)` are center-anchored billboards. `draw_line` with z is a world-thickness ribbon. Depth is LEQUAL + write. There is no OIT, no 3D text and no 3D rounded quads. A 3D call inside a 2D block warns and records nothing.
- **Layering in one render pass:** r2d first, then ImGui draw data, then the command queue.
- **Drop-never-defer:** the batch resets everywhere the write queue clears.
- **Descriptor sets:** keyed by frame slot, allocated at init or at that slot's flush, never touched by a swapchain rebuild. Every slot of a bound set must hold a valid view; freed rows park on white.
- **Swapchain drift:** same-format resize rebuilds nothing, format drift rebuilds both pipelines, and image-count drift rebuilds nothing.
- **Shader workflow:**
  - `cmake --build --preset debug --target ws_ui_regen_shaders` regenerates the header.
  - `--target ws_ui_check_shaders` checks for staleness (SKIPPED if no compiler).
  - `WS_UI_REGEN_SHADERS=ON` fails the build on a stale header.
  - Compiler resolution order: `-Compiler` / `WS_GLSLANG_EXE`, then `WS_GLSLANG`, then PATH, then `VULKAN_SDK\Bin`, then `%TEMP%\glslang-16.6.0`.
  - `WS_UI_DEV_SHADER_RELOAD=ON` (default OFF, Debug and desktop only) hot-reloads shaders, and a failed compile keeps the last good module.
  - `spirv.h` carries 3 arrays: vert, chunked frag, bindless frag.

## Immediate-mode gui (`ws::ui::gui`)

Widget functions hold no state; persistence lives in `GuiContext` side tables.

- **One seam:** identity, hit-test, layout and draw all come from the same rect and id.
- **Input:**
  - `frame_input()` is the per-frame `InputFrame`: mouse, `mouse_present`, `dt_seconds`, keys, and up to 8 touches.
  - `gather_pointers()` returns the mouse as slot 0 (only while `mouse_present`), then the touches.
  - `mouse_present` is set by desktop cursor move, button or enter, and cleared when the cursor leaves. On Android only the real-mouse path touches it.
  - The primary touch bridges to mouse button 0 but never touches `mouse_present`.
  - `begin_frame(frame_input())` adopts the snapshot, and `end_frame()` resolves per pointer.
- **Identity:** `WidgetId` is FNV-1a over scope + family tag + label.
  - `##` ids the full string but hides the tail.
  - `###` redirects the id from the marker onward.
  - `internal_id(key)` is the reserved family for gui state keys.
  - Loop children need `ids().push(index)`.
  - The census is 512 slots and warns once per duplicate.
- **Hot/active per pointer:**
  - One `PointerTrack` per pointer.
  - Press inside sets active (capture). Release inside is a click. Release outside is no click.
  - `hit_test` OR-folds pointers, and `HitTest::pointer` is the lowest slot.
  - `hovered` is the settled value (last frame's hot, gated on this frame's inside-ness).
  - Touch has no hover.
- **Layers:** base 10, popup 20, tooltip 30, modal 40, toast 50.
  - One numbering drives both hit-testing and `r2d::set_layer`.
  - A higher layer wins hot and steals a same-frame press. Within a layer the later widget wins.
  - A drag from an earlier frame is never stolen.
  - The modal veil is frame-wide, lifts at the next `begin_frame`, blocks lower strata, traps focus, and stashes and restores focus.
  - **Call modals before the widgets they block.**
- **Hit clips:**
  - `push_hit_clip` / `pop_hit_clip` / `current_hit_clip` mirror the r2d clip stack, and panels push both at the same rect.
  - A raw `r2d::push_clip` does not hit-clip.
  - `push_hit_clip_escape` is the popup/modal twin, pushed push-for-push with `r2d::push_clip_escape`. Tooltips push none.
  - Capture is never clipped.
- **State and focus:**
  - `state(id, bounds, disabled)` runs exactly one hit-test and returns `WidgetResult{hit, state}`. Priority: Disabled, then Pressed, then Hovered. Focus is the resting state.
  - `register_focusable(id)` (call order is Tab order, cap 128) is refused inside disabled scopes and under a modal veil.
  - Focus follows the press edge. Tab and Shift+Tab, `nav_next()` and `nav_previous()` resolve at `end_frame`, wrapping.
  - Also available: `is_focused`, `set_focus`.
- **Disabled scopes:** `begin_disabled(cond)` / `end_disabled()` / `disabled()`. Locked widgets claim nothing and the click passes through. Layer scopes reset the lock and restore it after.
- **Press cancel:** `cancel_pointer(id)` ends a press with no click. Cancelling a bridged touch cancels the mouse it mirrors, and vice versa.
- **Persistent state:** `persistent_state<T>(WidgetId)`. Eviction is explicit only (`clear_persistent_state()` or `clear_persistent_state(id)`), called between frames. Never use a local static.
- **Layout:** `LayoutCursor` with `next(w, h, align)`, `same_line(gap)`, `begin_panel(bounds, padding, spacing)` / `end_panel`, `remaining_width()`. A negative width fills the line. Align places within the line height so far, so place the tallest widget first. All four stacks (ids, panels, renderer clips, hit clips) cap at depth 8 with balanced overflow, and every pop is a no-op when empty.
- **Theme:** `ChromeTheme` / `kDefaultChrome`. It holds faces and metrics, including the `veil` face, `control_disabled`, `disabled_alpha` (0.45), `label_char_width`, scrollbar metrics, `drag_threshold`, `long_press_time` and `menu_open_delay`. `scaled(scale)` multiplies metrics (feed it `App::ui_scale()`). `dim(color, factor)` fades alpha only. `font` is a borrowed `const r2d::Font*` (null gives the label bars); the theme does not own it. Widgets take a `const ChromeTheme&` per call.
  - **Color** (`theme_color.hpp`): Oklch <-> rgb, `contrast_ratio`, `contrast_failures(theme)` (the checked pairs: AA text 4.5:1 against both backgrounds, `control_on`/`control_pressed` 3:1 as WCAG 1.4.11's state-carrying faces; hover is perceptual instead - 0.05 Oklab lightness off `control_bg`, never a WCAG pair), and `apply_accent(ChromeTheme&, accent)`: derives on/pressed/hovered/disabled from one color by walking Oklab lightness until the pairs clear. Semantic faces are never touched; an unwinnable accent lands best-effort and stays visible through `contrast_failures`. The color math is private to ui - promote to ws::math only if a second consumer appears.
  - **The document** (`theme_data.hpp`): `ThemeData` COMPOSES a `ChromeTheme` plus the non-widget tokens - font roles (`FontRole`: family + px), `icon_set`, shadow tokens, and the accent the faces were derived from (0 = stock). `default_dark()` / `default_light()` are the stock documents. It sits beside `ChromeTheme` so the widget contract and the constexpr stock chromes stay untouched; `apply_accent(ThemeData&, accent)` derives into the chrome and remembers the accent.
  - **Theme files** (`theme_json.hpp`): `read_theme(text, base, migrations)` -> `Result<ThemeData>` (parse + migrate + fold; never re-derives - the accent is data, an app wanting faces to follow calls `apply_accent` itself) and `write_theme` (canonical order, byte-stable; colors as `#RRGGBBAA`, the chrome's borrowed `font` never crosses). `ThemeFile` is the file layer: `load()` / `save()` / `poll()` - the hot-reload poller byte-compares on an injected clock (never mtime; the cadence starts at `load()`), and unknown top-level members are remembered for the next save, so load -> save -> load is byte-equal. `ThemeError` (category "ui": parse_failed / migrate_failed / io_failed / bad_value). All of it goes through the ws::settings json + `FileSystem` seam; the ws::settings link is PUBLIC because `FileSystem&` appears in this public header (the job_progress.hpp precedent).
- **Widgets:** `button`, `checkbox`, `radio`, `toggle_switch`, `collapsing_header`, `selectable`, `combo`, `text_input`, `slider_float`, `slider_int`, `drag_float`, `begin_panel` / `end_panel`, `tab_bar`, `begin_scroll_panel` / `end_scroll_panel`, the overlay scopes `begin_popup` / `begin_tooltip` / `begin_modal` (+ ends), `modal_dialog`, `menu_bar`, `context_menu`, `Toasts` + `draw_toasts`.
  - The statics `text` / `separator` / `progress` / `status_bar` take **no `GuiContext`**.
  - `spinner` and `progress_indeterminate` take the context only for the frame clock.
  - Every label goes through `fit_text` (display cut, then truncation to the longest fitting prefix + `...`, never splitting UTF-8).
  - Every interactive widget is a "citizen": focusable, driven through `state()`, with Enter/Space and arrows where relevant.
  - **The behavior/draw split:** every stateful family is two public halves - `<widget>_behavior` (the interaction and the citizenship ladder, answering a paint-ready result that folds `WidgetPaint`; draws nothing) and `<widget>_draw` (the stock look; no `GuiContext`, recomputing its own label fits) - and the composed widget is their thin fold. A custom look drives the behavior and paints its own pixels over the answer. The pairs cover button, checkbox, radio, toggle_switch, collapsing_header, selectable, slider, drag_float, spinner, progress_indeterminate, tab, combo and text_input (whose `EditBuffer` / `TextInputState` / `is_insertable` travel public with it), plus the scroll halves - `scroll_drag_behavior` / `scroll_thumb_behavior` / `scrollbar_draw`, with `ScrollState` public. `panel_draw`, `popup_placement` / `place_popup` and the menus' `MenuHoverState` fill the same seam. The statics (text, separator, progress, status_bar) are draw-only and unpaired. The gallery's "custom look" page shows the three combinations live.
  - Details to know:
    - `radio` writes `this_option` and reports only when the selection moved.
    - `selectable` doesn't write `selected`.
    - `combo` places its own dropdown (flips above if there's no room).
    - `text_input` edits ASCII 32..126 only, with a caller-owned NUL-terminated buffer, and returns true only when the text changed. Enter belongs to the caller.
    - The popup takes `bool& open` and closes on an outside press. The tooltip is chrome only. The modal takes `open` by value and never auto-closes.
- **Scrolling:**
  - Wheel claims are arbitrated: layer first, then innermost bounds, then registration order, with the winner published for the next frame (one frame of lag by design).
  - A touch drag uses a per-pointer scroll arm, and `drag_threshold` triggers `cancel_pointer`.
  - Tab scrolls the focused widget into view.
  - The scrollbar thumb is grabbable.
  - Scroll is vertical only.
- **Menus:** `MenuItem` arrays are per-frame data. A `MenuEvent.item` pointer is identity-compared against this frame's arrays. `&X` mnemonics, hover switching, submenu delay, and Esc / outside press close the chain. `context_menu` opens at the press point (right-click or long-press).
- **Dialogs:** `modal_dialog(gui, theme, label, title, DialogButtons, bool& open, width = 360, body = {})`. Stock sets: none / ok / ok_cancel / yes_no / retry_cancel. Escape answers the negative, and Enter answers the positive but never on the opening frame.
- **Toasts:** 8 slots, borrowed text, `duration <= 0` is sticky, and `draw_toasts` runs once per frame.
- **The jobs bridge** (`job_progress.hpp`): `JobProgress` (one mirror per job, filled by the drain's `on_progress` deliveries), `job_view()` (the pure `JobState`-to-look mapping: fill face, word, cancellable — the scripted-states test seam), the `job_progress()` row widget ("label: state" line, state-colored bar, cancel button wired to `request_cancel()`), and `toast_on_failure()` (a failed job formats its error into a caller-owned long-lived string and posts one error toast; cancelled is not a failure; the Result crosses back). The bar's color rides `control_on` through a local theme copy, so no widget grew a color parameter. All of it assumes the App seam: the drain that fills the mirrors runs on the gui's own thread, so the mirrors are plain unlocked state.
- **Scope guards** (`scoped.hpp`): `ScopedLayer`, `ScopedDisabled`, `ScopedPanel`, `ScopedScrollPanel`, `ScopedPopup`, `ScopedTooltip`, `ScopedModal`. Header-only, copy and move deleted, and the overlay guards gate their end on the begin's answer.
- **Everything is drop-safe headless**, so the whole gui tests without a window.

## Public API

- `App(config)` / `App::run()` returns 0 on success or 1 on startup failure. `AppConfig` holds title, size and vsync.
- `on_setup()`: called once after the GPU and ImGui/ImPlot contexts are up. Load fonts and textures here.
- `on_event(Event&)`: once per queued event, before `on_update()`.
- `on_update()`: once per frame. **Do not call `ImGui::Render()` or the backend NewFrame functions**; the shell owns the frame lifecycle.
- `ui_scale()`: Android density / 160, or the desktop content scale. It is 1.0 before `run()` and valid from `on_setup()`.
- `prefers_dark()`: the OS dark-mode answer, live per call — Windows reads the Personalize registry value (advapi32, linked PRIVATE), Android the glue's `AConfiguration` night mask, and a probe-less platform answers false (light). Neither platform offers a theme-change event, so nothing is cached: callers ask rarely (a stock theme picked once at startup). It is false before `run()`, valid from `on_setup()`. The platform half lives in `WindowHost::prefers_dark()` (a defaulted virtual — the stub answer where no probe exists).
- `install_clipboard(gui::GuiContext&)`: call once in `on_setup()`. Desktop installs the real pair. Android leaves it unset, so the clipboard trio no-ops.
- `install_job_system(ws::jobs::JobSystem&)`: call once in `on_setup()`. The shell drains the system's marshal queue once per frame, between the event delivery and `on_update()` — progress deliveries and completions run on the main thread, outside any gui frame, so callbacks may touch gui state (the `Toasts` store, a `JobProgress` mirror) with no locks. The system is caller-owned and must outlive `run()` (or be drained by hand before it is destroyed).
- `widgets.hpp`: `begin_window` / `end_window`, `text`, `button`, `checkbox`, `slider_float` / `slider_int`, `separator`, `same_line`, `begin_plot` / `end_plot` / `plot_line`, `show_imgui_demo` / `show_implot_demo`.

## Backend invariants

- **Device selection** requires `shaderSampledImageArrayDynamicIndexing`.
- **Texture tier probe** (in `gfx::Gpu`, once per process): bindless needs `shaderSampledImageArrayNonUniformIndexing` + `descriptorBindingPartiallyBound` (+ update-after-bind if present) and limits that cover 1024 slots. Any miss falls back to chunked, never a failure. It logs one `gfx:` info line.
- **Swapchain** (`gfx::Swapchain`):
  - `minImageCount + 1` images, BGRA8 preferred, FIFO with vsync, mailbox/immediate otherwise.
  - Recreated on resize, out-of-date or suboptimal through the same `WindowResizeEvent` path.
  - An out-of-date acquire drops the frame. A suboptimal acquire still renders and presents, and the rebuild lands afterwards.
- **Frames in flight:** `gfx::kMaxFramesInFlight` = 2, pinned equal to `r2d::kMaxFramesInFlight` by a static_assert in `app.cpp`. The fence is waited before acquire and reset only after a successful acquire. Each slot owns a fence, command pool/buffer and acquire semaphore, and each swapchain image owns its render-finished semaphore.
- **Render pass:** always color + depth, with explicit external subpass dependencies (they prove the shared depth image is safe). The depth format is chosen once (D32 → D24S8 → D16), clears to 1.0, and uses LEQUAL. r2d builds two pipelines against the pass: depth-off and depth-on.
- **Validation:** opt-in through the `WS_UI_VALIDATION` env var (not public API). Without the SDK it warns once and runs without. Sync validation only runs under the opt-in.
- **ImGui Vulkan backend:** MinImageCount 2. The shell re-inits it if the image count or format changes.
- **Exceptions:** exceptions in `on_event` / `on_update` are caught, logged, and close the window cleanly (an `on_update` exception abandons the frame with no `Render()`).
- **Failures:** mid-frame Vulkan failures log and `std::abort()`. Startup failures return 1 from `App::run()`.
- **Input platform rules:**
  - Desktop is mouse-only by decision (no WM_POINTER).
  - Android decodes every contact (pointer index from the action bits), CANCEL lifts all, and the 9th and later fingers drop with a once-per-frame warning.
  - ImGui is fed by the bridge directly through `io.AddMousePosEvent` / `AddMouseButtonEvent`.
  - The Android soft-keyboard IME is out of scope for v1.

## Implementing new features

1. Design the public API first, backend-agnostic, and check it against the no-leak rule.
2. Implement the GLFW/Vulkan/ImGui-specific pieces under `src/`.
3. Route GPU work through `RenderCommandQueue`, or the r2d API for 2D drawing.
4. Confirm a consumer could include only `include/ws/ui/*.hpp` and never need Vulkan/GLFW/ImGui headers at compile time.

## Known v1 limits (deliberate)

- The gui is screen-space only, and scroll is vertical only.
- `text_input` has no horizontal scroll and edits ASCII only.
- No popup Escape-close or auto-flip. The combo handles its own flip.
- The popup padding rim passes input through.
- No OIT, and no 3D text or rounded quads.
- Fonts have no kerning and are never rescaled at runtime — a size change is a new font (its lazy glyphs re-request on first use). The face stack grows a font past ASCII without a re-bake, but the primary path stays `load_font`. Font paths are supplied by the caller, which is Windows-only in practice today.
- The Android soft-keyboard IME is unsupported.
- No directional or gamepad focus nav yet. The focusable list is the seam for it.
- Handle generation wraps after 4096 reuses of one slot. The bindless table is capped at 1024 slots.
